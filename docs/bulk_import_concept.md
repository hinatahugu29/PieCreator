# PieCreator: Bulk Import & Menu Scraping Concept

## 1. 背景と目的
PieCreatorは現在、個別のコマンドやマクロを自由に登録できる強力なツールへと進化しています。
しかし、大規模なワークフロー（例：すべてのメッシュ追加、すべてのシェーダーノードなど）を構築する際、一つ一つ手動で登録するのは依然として手間がかかります。

本コンセプトは、**「Blenderに既に存在する資産（メニューやノード構造）をごそっと取り込む」**ことで、構築コストを劇的に下げ、ユーザーの創造性を最大化することを目指します。

---

## 2. コア・アイデア

### A. メニュー・スクレイピング (Menu Scraping)
Blenderの既存メニュー（標準メニュー、および他アドオンのカスタムメニュー）の内容を解析し、アイコン、ラベル、コマンドをセットとして一括抽出する機能。

*   **活用例:** 「追加 > メッシュ」の内容をすべて取り込み、自分流に並べ替えたPieメニューを30秒で作成。
*   **強み:** 外部アドオンによって追加された項目（例：Quad Sphereなど）も自動で認識・抽出可能。

### B. ノード・パレット生成 (Node to Palette)
アクティブなノードツリーやノードグループ内の「使われているノード」を解析し、それらを呼び出すための専用メニューを自動生成する機能。

*   **活用例:** 「ライティング用ノード一式」をメニュー化し、シェーダー構築を加速させる。

---

## 3. 技術的アプローチ

### メニュー解析の仕組み（レイアウト・ハイジャック）
Blenderのメニュー定義はPythonの `draw` メソッド内で実行されます。これを直接解析する代わりに、以下の手法を検討します。

1.  **Mock Layout オブジェクトの作成:** `UILayout` クラスを模したダミーオブジェクトを作成し、`operator()` や `menu()` といったメソッドが呼ばれた際にその引数を記録するように設計します。
2.  **実行:** ターゲットとなるメニューの `draw` 関数を、この Mock Layout を渡して実行します。
3.  **データ化:** 記録された「どのオペレーターが、どのアイコンで、どの名前で呼ばれたか」という情報を JSON 形式で PieCreator のストレージへ書き出します。

### ノード連携の仕組み
`bpy.data.node_groups` または `context.space_data.edit_tree` を走査し、ノードの `bl_idname` を抽出します。これを `node.add_node` オペレーターの引数としてメニュー項目に変換します。

## 4. UI/UX デザイン案

### インポート・ウィザード
*   **魔法の杖アイコン:** 編集画面に「既存資産から抽出」ボタンを配置。
*   **プレビュー機能:** 抽出された項目をリスト表示し、チェックボックスで「取り込む項目」を選択可能にする。
*   **スマート・マージ:** 既存のメニューに「追加」するか、新しいメニューとして「作成」するかを選択。

## 5. 期待される効果
1.  **導入障壁の撤廃:** PieCreatorをインストールしたその日に、お気に入りのメニューをすべてPie化できる。
2.  **エコシステムの統合:** 他のアドオンとPieCreatorが、コードを書くことなくシームレスに連携。
3.  **プロフェッショナル・ワークフロー:** 複雑なノード作業を「自分専用の物理ボタン」感覚で操作可能。
